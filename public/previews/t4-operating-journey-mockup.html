Diagnosis · เลือกงานให้ถูก

AI ยังไม่ใช่คำตอบ ถ้าทีมยังอธิบาย งานเดิม ไม่ตรงกัน

Fit Gate จึงเริ่มจากงานซ้ำ ความถี่ Process owner และความเสี่ยงของข้อมูล ไม่ได้เริ่มจากถามว่าจะใช้ Tool ตัวไหน

01

งานซ้ำ แต่ไม่มีใครเห็นทั้ง Flow

แต่ละคนรู้เฉพาะช่วงที่ตัวเองทำ จึงไม่รู้ว่าความล่าช้าหรือข้อมูลขาดเกิดตรงไหน

02

ซื้อ Tool แล้ว แต่ทีมยังทำแบบเดิม

เครื่องมือถูกเพิ่มเข้าไปโดยที่ Owner, Rule และ Exception ของงานยังไม่ถูกตกลง

03

อยากให้ AI ทำแทน แต่ไม่รู้ว่าคนต้องตรวจอะไร

เมื่อไม่มี Human review ที่ชัด ทีมไม่รู้ว่า Output ไหนใช้ต่อได้และใครรับผิดชอบ

04

Demo ผ่าน แต่ไม่รู้ว่าควรลงทุนต่อไหม

ไม่มี Test record หรือ Decision Memo จึงตัดสินใจจากความรู้สึกแทนหลักฐาน

ขอบเขตตั้งใจให้เล็ก: หนึ่งบริษัท · หนึ่งวัน · หนึ่ง Workflow

Workshop นี้ไม่ใช่ Production build, Live integration, migration หรือ SLA หาก Fit แล้วต้องเชื่อมข้อมูลจริง ให้แยก Scope ไปบริการ I1

Curriculum · จากงานเดิมไปถึงคำตัดสิน

ทุกช่วงต้องจบด้วยสิ่งที่ทีมถือกลับไปใช้ต่อได้

ไม่สอน Tool เรียงตามเมนู แต่พาทีมเดินตามงานหนึ่งเส้น ตั้งแต่เลือกโจทย์จน Owner ลงข้อสรุป

  1. 01
    Fit Gate

    เลือกงานที่ควรทดลองก่อน

    Pick

    เข้าใจอะไรงานซ้ำอะไร เกิดบ่อยแค่ไหน ใครเป็น Process owner และมีข้อมูลเสี่ยงหรือไม่

    ลงมือทำเลือก Candidate หนึ่งเรื่องที่ทีมอธิบายงานเดิมและความเสี่ยงได้

    ได้อะไรกลับไปFit decision + ขอบเขตหนึ่ง Workflow

  2. 02
    ช่วงที่ 1

    เห็นงานเดิมก่อนให้ AI แตะงาน

    Map

    เข้าใจอะไรTrigger, Input, Rule, Exception, Output และขั้นที่คนต้องตัดสิน

    ลงมือทำทำ Workflow Map จากตัวอย่างงานที่ปิดข้อมูลสำคัญแล้ว

    ได้อะไรกลับไปWorkflow Map ฉบับบริษัท

  3. 03
    ช่วงที่ 2

    สร้างที่ทดลองให้ทีมลองรันเอง

    Sandbox

    เข้าใจอะไรข้อมูลจำลอง เส้นทางทดสอบ จุดหยุด และเกณฑ์ที่ถือว่าผลใช้ได้

    ลงมือทำให้ Core build team รัน Flow ตั้งแต่ Input ถึง Output

    ได้อะไรกลับไปSafe Sandbox Prototype + Test record

  4. 04
    ช่วงที่ 3

    ล็อกว่าคนต้องตรวจและรับผิดชอบตรงไหน

    Responsibility

    เข้าใจอะไรAI ช่วยเตรียมหรือจัดรูปแบบได้ แต่คนยังตรวจ อนุมัติ และสื่อสารในจุดที่มีผลจริง

    ลงมือทำเขียนจุด Human review จาก Flow ที่ทีมเพิ่งทดสอบ

    ได้อะไรกลับไปHuman–AI Responsibility Brief

  5. 05
    ช่วงที่ 4

    เลือก Stop, Revise หรือ Install

    Decide

    เข้าใจอะไรตัดสินจากสิ่งที่รันได้จริง ความเสี่ยง และสิ่งที่ต้องเตรียมก่อนขยาย

    ลงมือทำให้ Owner/Manager ลงข้อสรุปและ Next step ที่มีเจ้าของ

    ได้อะไรกลับไปStop / Revise / Install Decision Memo

01 · เห็นงานเดิม

Workflow Map

ใช้ทวนว่า Flow เริ่มและจบที่ไหน พร้อม Rule และ Exception ที่ทีมพบ

02 · เห็นสิ่งที่ลอง

Sandbox + Test Record

ใช้ดูว่าเส้นทางไหนรันได้ จุดไหนยังติด และข้อมูลแบบใดถูกใช้ในการทดลอง

03 · เห็นคนรับผิดชอบ

Responsibility Brief

ใช้ล็อก Human review, Owner และสิ่งที่ห้ามให้ AI ตัดสินแทน

04 · เห็นทางต่อ

Decision Memo

ใช้ลงข้อสรุป Stop, Revise หรือเตรียม Scope สำหรับ Production build

Fit · เหมาะเมื่อ

ทีมพร้อมทดลองงานหนึ่งเรื่องให้เห็นจริง

  • มีงานซ้ำที่เกิดบ่อยและมี Process owner ชัด
  • ทีมอธิบาย Input, Rule, Exception และ Output ได้
  • พร้อมใช้ dummy data หรือข้อมูลที่ Mask แล้ว
  • Owner พร้อมลงข้อสรุปหลังดู Test record

Not fit · ควรเริ่มทางอื่นเมื่อ

โจทย์ยังใหญ่กว่าหนึ่ง Workflow หรือยังไม่มีเจ้าของงาน

  • ยังเลือก Process สำคัญไม่ได้ — เริ่ม C1 เพื่อจัด Priority
  • ต้องเชื่อม Live data หรือระบบ Production — แยก Scope ไป I1
  • ต้องการหลาย Workflow, migration, integration หรือ SLA
  • คาดหวังให้ AI ตัดสินใจแทนคนหรือลดคนทันที

Investment · ก่อนล็อกวัน

ผ่าน Fit Gate ก่อนออกใบแจ้งหนี้

ส่งงานซ้ำ ความถี่ Process owner และข้อมูลเสี่ยงที่เกี่ยวข้องมาให้ดูก่อน เพื่อยืนยันว่าขอบเขตพอทำ Pilot ในหนึ่งวันได้

เงื่อนไข: ชำระค่าบริการ 100% ก่อนวันอบรมเพื่อยืนยันคิว ค่าเดินทางนอกพื้นที่มาตรฐานจะแจ้งก่อนล็อกวัน
